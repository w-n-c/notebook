### 1. ADR ↔ Spec Contradictions & Drift

  • Inline Style Scope Override (ADR 0001 & ADR 0003 vs. Spec)
      • docs/adr/0001-virtual-layout-tokens-via-data-attributes.md:7-13 states layout primitives avoid inline styles to prevent "CSP violations
      from inline styles," while docs/adr/0003-ai-coding-agent-guardrails-and-verification.md:15 enforces "Zero Inline Styles in Layouts" only on
      .astro layout components.
      • .scratch/site-foundations/spec.md:47 explicitly permits higher-level display components to use inline styles (style="...") as an escape
      hatch. If display components emit inline styles, any strict style-src Content Security Policy (cited as a rationale in ADR 0001) will break
      unless unsafe-inline is enabled.
  • SearchDocument Normalization Drift (ADR 0002 vs. Spec & Issues 02/03)
      • docs/adr/0002-hybrid-search-dynamic-views-and-llm-synthesis.md:11 mandates that all notes and projects normalize into a unified
      SearchDocument format (which includes timestamps and privacy/staging metadata).
      • .scratch/site-foundations/spec.md:40-41 and .scratch/site-foundations/issues/03-projects-collection-portfolio-grid.md:9 omit any
      date/timestamp field (pubDate or updatedDate) on projects, making chronological sorting or unified SearchDocument timestamp normalization
      impossible without a schema migration in Slice 3.
      • Neither notes nor projects schemas in .scratch/site-foundations/spec.md:36-42 include a draft or isPrivate boolean field to guard against
      accidental publication of WIP/private notes referenced in docs/adr/0003-ai-coding-agent-guardrails-and-verification.md:13.
  • Ubiquitous Language Drift (GLOSSARY.md vs. Spec & Issues)
      • GLOSSARY.md:9-11 forbids "Layout component" in favor of Layout Primitive, yet
      docs/adr/0003-ai-coding-agent-guardrails-and-verification.md:15 and .scratch/site-foundations/spec.md:26 use "layout components".
      • .scratch/site-foundations/issues/02-notes-collection-index-reader.md:9-11 defines description in the Zod schema on line 9, then refers to
      rendering summary on line 11.

  ### 2. Spec ↔ Existing Code Mismatches

  • astro check Gate Missing Dependency & Hook Enforcement
      • docs/adr/0003-ai-coding-agent-guardrails-and-verification.md:19, .scratch/site-foundations/spec.md:51, and
      .scratch/site-foundations/issues/04-home-landing-accessibility-gate.md:12 require bun run astro check to pass with zero diagnostics.
      • Mismatch 1: @astrojs/check is not installed in package.json:15-26. Running bun run astro check in a non-interactive shell/CI will prompt
      to install @astrojs/check and fail or hang.
      • Mismatch 2: scripts/git-guardrails.sh:28-32 only runs bun test and never invokes astro check or astro build, nor does it block the
      destructive git commands (git push --force, git reset --hard, git branch -D main) claimed in
      docs/adr/0003-ai-coding-agent-guardrails-and-verification.md:20-21.
  • Theme Tokens Defined in :root Are Never Applied to body
      • .scratch/site-foundations/spec.md:33 states: "The root document body applies standard typography tokens and theme canvas backgrounds
      defined in global CSS."
      • In src/styles/global.css:48-61, --bg-canvas and --text-main are declared on :root, but body only sets font-size, line-height, and margin:
      0—it never sets background-color: var(--bg-canvas); color: var(--text-main);.
      • Furthermore, src/styles/global.css is currently imported inside the throwaway src/components/Welcome.astro rather than
      src/layouts/Layout.astro:1-23, and Layout.astro still contains unlayered `<style> overrides (html, body { width: 100%; height: 100%; })` that
      trump @layer base.
  • Global 65ch Measure Trap on Semantic HTML5 Containers
      • src/styles/global.css:84-109 sets * { max-inline-size: var(--max, var(--measure)); } (65ch) and only exempts html, body, div, header, nav,
      main, footer.
      • All 10 layout primitives support polymorphic <Component as="..." /> (e.g., `<Grid as="ul">, <Cover as="section">, <Box as="article">, <Stack as="ol">`). Because section, article, aside, ul, and ol are missing from src/styles/global.css:101-109, any semantic multi-column
     `<Grid as="ul"> or full-bleed <Cover as="section">` will silently collapse to 65ch wide.

  ### 3. Underspecified Seams (Where an Implementation Agent Will Guess)

  • Astro 7 Content Layer API vs. Legacy Astro v4 Collections
      • Quote: .scratch/site-foundations/spec.md:38-39 — "Content lives as markdown/MDX files. Dynamically generates single-entry routes matching
      each file's slug." & .scratch/site-foundations/issues/02-notes-collection-index-reader.md:12 — "/notes/[slug] dynamically renders markdown
      body".
      • Missing Decision: package.json:17 uses "astro": "^7.3.8". In Astro 5+, src/content/config.ts, entry.slug, and entry.render() are replaced
      by the Content Layer API (src/content.config.ts at root, glob() loader, entry.id, and render(entry) imported from astro:content). Without
      explicit instruction, an LLM agent trained on Astro v2–v4 will scaffold src/content/config.ts and entry.slug, failing compilation in Astro 7.
  • projects Schema category and metrics Shapes
      • Quote: .scratch/site-foundations/spec.md:41 — "Schema requires title, description, category (e.g. distributed systems, cloud
      infrastructure, AI engineering), tags, featured (boolean flag), optional metrics (key-value summary of performance impact), and optional
      repoUrl."
      • Missing Decision:
          1. Is category a closed z.enum([...]) (if so, what is the exact list?) or an open z.string()?
          2. Is metrics a z.record(z.string(), z.string()) (e.g. {"Throughput": "50k msg/s"}) or an array of { label: string, value: string }
          objects?

  • Unit Testing Content Schemas Outside Astro's Vite Pipeline
      • Quote: .scratch/site-foundations/issues/02-notes-collection-index-reader.md:13 — "Automated schema test verifies that missing required
      frontmatter throws compilation/validation errors."
      • Missing Decision: bun test runs outside Astro's Vite virtual module runtime, so importing defineCollection or z from 'astro:content'
      directly inside a tests/*.test.ts file will throw a module resolution error unless pure Zod schemas are exported from a standalone module
      (e.g., src/schemas/content.ts using astro/zod) and imported by both src/content.config.ts and tests/.
  • axe-core Execution Environment Without a Browser
      • Quote: .scratch/site-foundations/issues/04-home-landing-accessibility-gate.md:11 — "Automated accessibility audit (axe-core) runs across
      all primary routes (/, /notes, /projects, /notes/[slug]) verifying 0 WCAG 2.1 AA violations."
      • Missing Decision: Neither axe-core nor a DOM shim (happy-dom / jsdom) is in package.json. Furthermore, running axe-core inside
      jsdom/happy-dom against static dist/**/index.html files cannot evaluate CSS light-dark() color contrast (mentioned in
      .scratch/site-foundations/spec.md:55) because non-browser DOM shims lack a layout/computed-color engine for light-dark().
  • Home Page Curated Limits & Social URLs
      • Quote: .scratch/site-foundations/issues/04-home-landing-accessibility-gate.md:9-10 — "/ presents a concise bio (Senior Systems/Cloud
      engineer building in AI & open web) with social links (GitHub, LinkedIn, Bluesky). Displays featured projects dynamically from the projects
      collection and recent notes from the notes collection."
      • Missing Decision: Exact URLs/handles for GitHub, LinkedIn, and Bluesky (or whether placeholder/config constants should be used), and how
      many recent notes (e.g., top 3? top 5?) should render on /.

  ### 4. Second-Order Failure Modes & Edge Cases

  • Scoped Astro Styles vs. Markdown Prose Rhythm in /notes/[slug] and /projects/[slug]
      • `<Stack>` relies on an Astro-scoped selector `(.stack[data-astro-cid-xxxx] > * + *)`. When markdown content is rendered via `<Content />` inside
      `<Stack>`, only the direct children receive data-astro-cid-xxxx in some Astro compilation modes, or if <Content /> is wrapped in an `<article>`,
      its internal `<p>, <h2>, <ul>, <pre> ` tags will have margin: 0 (from h1-h4 resets in src/styles/global.css:63-82) and zero vertical spacing
      unless .stack uses` :global(> * + *)` or a dedicated prose rhythm rule is applied.
  • Wide `<pre><code>` Blocks Blowing Out Mobile Viewport Inside `<Center>`
      • In src/styles/global.css:84-87, `* { max-inline-size: var(--max, var(--measure)); }` caps elements to 65ch, but `<pre>` blocks in technical
      notes without overflow-x: auto will force horizontal viewport overflow on narrow mobile screens (320px).
  • Pre-Commit Hook Latency & Staged-vs-Working-Tree Desync
      • scripts/git-guardrails.sh:21 checks grep ... "$file" on the working tree file rather than git show ":$file" (the staged index), meaning
      unstaged working-tree edits can falsely trip or bypass the pre-commit check. Additionally, if astro build is added directly to pre-commit
      (rather than CI or a pre-push/test gate), every commit will incur a full static site build delay.

  ### 5. Blocking Questions Before Implementation (Max 5)

  1. Astro 7 Content Layer & Schema Test Seam: Should we use Astro 7's Content Layer API (src/content.config.ts with glob() loader) and export the
  raw Zod schemas from a shared src/schemas/content.ts file so bun test can unit-test frontmatter validation directly without booting Vite?
  2. projects & notes Schema Contracts:
      • In projects, should category be a strict z.enum(['distributed-systems', 'cloud-infrastructure', 'ai-engineering']) or freeform z.string(),
      and should metrics be z.record(z.string(), z.string()) or z.array(z.object({ label: z.string(), value: z.string() }))?
      • Should both notes and projects include draft: z.boolean().default(false) (and pubDate on projects) now so they cleanly map to
      SearchDocument in Slice 3?
  3. axe-core Accessibility Gate Mechanism: Since bun test has no real browser engine to compute CSS light-dark() contrast, should the axe-core
  gate in Ticket 04 run in bun test via happy-dom against the built dist/**/*.html output (checking structural/ARIA WCAG 2.1 AA rules) paired with
  a deterministic contrast ratio unit test on the hex tokens in global.css?
  4. Global CSS Semantic Tag Exemptions & Prose Rhythm: In src/styles/global.css:101-109, can we add section, article, aside, ul, ol to the max-
  inline-size: none container list (leaving text elements like p, li, h1-h6, blockquote capped at 65ch) and apply background-color: var(--bg-
  canvas); color: var(--text-main); to body?
  5. Social Links & Home Page Limits: What social URLs (or site config placeholders) and maximum count of "recent notes" (e.g., 3) should Ticket
  04 render on /?
